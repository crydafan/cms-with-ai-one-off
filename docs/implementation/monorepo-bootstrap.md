# Monorepo Bootstrap Implementation Record

## Scope

This change establishes the repository layout and runnable application shells for the AI-assisted CMS prototype. It creates a Next.js App Router frontend in `apps/web` and a FastAPI backend in `apps/api`, with root-level pnpm workspace management and app-local Python dependency management through uv.

The implementation was committed as `30a65aa` (`chore: scaffold FastAPI and Next.js monorepo`).

## Technical approach and decisions

- The root `pnpm-workspace.yaml` includes `apps/web`; the single root `pnpm-lock.yaml` owns JavaScript dependency resolution.
- The frontend uses Next.js 16, React 19, Tailwind CSS, and shadcn initialized with the Base Nova style. Alert, badge, button, input, skeleton, and textarea primitives are present for upcoming slices.
- The backend is a `src`-layout Python package managed by uv. Its dependency set includes FastAPI, SQLAlchemy, Alembic, OpenAI, Pydantic Settings, and Uvicorn for the planned vertical slices.
- Backend settings read environment variables and an app-local `.env`. SQLite, local frontend CORS, and DeepSeek's OpenAI-compatible base URL/model have development defaults. The DeepSeek API key is represented as a secret and is configured only in the backend environment.
- The backend currently exposes `/health` and permissive local development CORS for the frontend origin. The health check does not call DeepSeek or depend on database availability.
- Root `.env.example` documents backend and frontend variables. Root `README.md` explains which values belong in `apps/api/.env` and `apps/web/.env.local`, and how to install and run each app.
- `apps/web/AGENTS.md` and `apps/web/CLAUDE.md` are generated by the installed Next.js version. The Next.js agent note says `next dev` regenerates the file, so it is retained to keep the working tree clean after startup.

## Deviations and reasons

- `pnpm install` initially paused because the dependency `unrs-resolver` requested an install build script. That dependency was reviewed and explicitly approved with `pnpm approve-builds`, after which installation completed. The workspace records the approval in `pnpm-workspace.yaml`.
- The generated frontend scaffold included its own lockfile. It was removed so the monorepo uses one root lockfile, consistent with the workspace setup.
- No product features, persistence schema, database migration, AI workflow, reader routes, or writer routes were implemented; this change is limited to application shells and setup.

## Verification

- `pnpm install` from the repository root completed successfully.
- `pnpm --filter @cms/web dev` started Next.js 16.3.6 and reached its ready state.
- `uv lock` and `uv sync` completed from `apps/api`.
- `uv run uvicorn cms_api.main:app --reload` started the API, and `GET /health` returned HTTP 200 with `{"status":"ok"}`.
- `git diff --cached --check` passed before the scaffold commit.
- No automated tests or production builds were run; neither is part of this bootstrap record's verification.

## Remaining limits

- The frontend is still the default Next.js starter screen; reader and writer experiences remain to be built.
- The API only provides a health endpoint. Database models, migrations, draft persistence, AI generation, publishing, and article retrieval remain unimplemented.
- The writer route is intended to be hidden by URL and is not protected by authentication in this prototype.
- DeepSeek credentials and live provider calls were not exercised. Local startup and health verification do not validate provider configuration.
- SQLite and local CORS defaults are for development and do not define production deployment settings.
